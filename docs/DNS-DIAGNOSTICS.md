# Диагностика DNS

[Вернуться к настройке](../README-RU.md#настройка) · [English](DNS-DIAGNOSTICS.en.md)

Счётчик «Ошибки» в LuCI показывает сбои разрешения имён и маршрутизации DNS. Отклонения входящих пакетов учитываются отдельно: например, запрос с двумя вопросами или незаполненной секцией получает ошибку формата. Эти события не означают, что соединение с DNS-провайдером перестало работать.

## Данные для отчёта

Выполните в SSH-консоли роутера:

```sh
resproxyd version
cat /var/run/resproxy/dns-status.json
cat /var/run/resproxy/dns-upstream-errors.json
```

Укажите, появились ли ошибки после запуска или продолжают расти при обычной работе. Для разбора отклонений добавьте:

```sh
jsonfilter -i /var/run/resproxy/dns-rejected.json -e '@.recent_samples'
```

Эти файлы содержат счётчики, причины ошибок, адреса клиентов и числовые поля заголовков. Доменов, ссылок подписок и содержимого пакетов в них нет. Перед публикацией можно скрыть локальные IP-адреса.

## Счётчики

`dns-status.json` содержит общие счётчики запросов, ошибок и отклонений. В `dns-upstream-errors.json` есть отдельные разделы `proxy` и `wan` с причинами неудачных обращений к резолверу.

| Поле | Значение |
|---|---|
| `dns_failures` | Клиентские запросы с ошибкой DNS или маршрутизации |
| `failure_endpoint` | Некорректный адрес резолвера или отсутствие обнаруженного WAN DNS; это не число недоступных прокси-узлов |
| `failure_invalid_query` | Отклонённые входящие пакеты |
| `failed_exchanges` | Неудачные обращения к резолверу |
| `recent_samples` в `dns-upstream-errors.json` | Последние восемь неудачных обращений для каждого пути |
| `questionless_failed_exchanges` | Неудачные обращения без DNS-вопроса; они входят в общий счётчик |
| `unsupported_opcode` | Запросы с неподдерживаемой операцией, на которые обработчик ответил локально |

Несколько одинаковых клиентских запросов могут использовать одно обращение к резолверу. Поэтому число клиентских ошибок и `failed_exchanges` может различаться. Ответ `NOTIMP` на устаревший IQUERY учитывается в `unsupported_opcode`.

Если XRoute не может прочитать состояние WAN, он повторяет чтение с увеличением паузы. После успешного чтения повторы прекращаются. При подтверждённом отключении WAN старый DNS не используется.

Счётчики накапливаются за время работы текущего процесса DNS. Сравните два снимка, чтобы отличить прошлые ошибки от продолжающегося сбоя. Ошибка выбора резолвера может произойти до сетевого обращения, поэтому записи о ней в `dns-upstream-errors.json` может не быть. Время таких отказов агрегатные счётчики не сохраняют.

При сбое запуска или восстановления сети добавьте вывод `resproxyd doctor`. Сохранённая запись инцидента содержит только время, стадию и результат очистки, без ссылок подписок и паролей.
